# Design: Go REST API Template (Gin + Swag + GORM)

**Date:** 2026-08-07
**Status:** Approved

## Purpose

A reusable backend scaffold for building REST APIs in Go, demonstrating user
authentication (JWT + roles) and one sample protected CRUD resource (Todo),
documented with Swagger via Swag/gin-swagger, backed by Postgres (Neon)
through GORM.

## Tech Stack

- **HTTP:** Gin
- **API docs:** Swag + gin-swagger (generated `docs/`, UI at `/swagger/index.html`)
- **Database access:** GORM (Postgres driver, works with the Neon connection string in `.env`)
- **Auth:** golang-jwt/v5 for tokens
- **Password hashing:** `golang.org/x/crypto/bcrypt`
- **Config:** `.env` via `godotenv` + OS env vars

## Data Model

`User`
- id (PK, auto)
- email (unique, indexed)
- password_hash
- role (`admin` | `user`)
- created_at / updated_at

`Todo`
- id (PK, auto)
- title
- description
- done (bool, default false)
- owner_id (FK -> users.id)
- created_at / updated_at

Relationships: `User` has many `Todo`; `Todo` belongs to `User`.

## Endpoints

Public:
- `GET  /healthz` — simple health check returning `{"status":"ok"}`.
- `POST /api/v1/auth/register` — create a `user`-role account. Validates email format and password length, hashes with bcrypt. Returns the created user (no password).
- `POST /api/v1/auth/login` — verify email+password, return `{ token }` (JWT with `sub`=user id and `role` claim).

Auth-required (middleware `RequireAuth`):
- `GET    /api/v1/users/me` — current user profile.
- `GET    /api/v1/todos` — list todos owned by the current user.
- `POST   /api/v1/todos` — create a todo for the current user.
- `GET    /api/v1/todos/:id` — fetch one todo (owner or admin).
- `PUT    /api/v1/todos/:id` — update own todo (owner or admin).
- `DELETE /api/v1/todos/:id` — delete own todo (owner or admin).

Admin-only (middleware `RequireRole("admin")` after `RequireAuth`):
- `GET /api/v1/users` — list all users.

All endpoints documented with swag annotations and registered against `router/api/v1/todo` etc.

## Flow Details

**Auth flow**
1. `POST /login` -> verify email exists, `bcrypt.CompareHashAndPassword`.
2. On success sign JWT: subject = user id, claim `role`, expiry ~24h, signed with `JWT_SECRET` from env.
3. `RequireAuth`: read `Authorization: Bearer <token>`, parse/validate, load the user into Gin context.
4. `RequireRole("admin")`: assert the `role` claim.

**Error handling**
- Uniform JSON responses: `{ "error": "<message>" }`.
- Correct HTTP status codes (400, 401, 403, 404, 409, 500).
- A small error helper to keep handlers consistent.

## Configuration (.env)

- `PORT` (default `8080`)
- `POSTGRESQL_DATABASE` (Neon URL already present in `.env`)
- `JWT_SECRET`
- `TOKEN_HOURS` (default 24)
- `GIN_MODE` (default `debug`)

## Migrations

- Primary: GORM `AutoMigrate` on startup for `User` and `Todo`.
- No external migration tool in this template (scope kept small); structure makes a later switch to golang-migrate straightforward.

## Testing

- `go test ./...`
- Unit tests for the JWT middleware (valid/invalid/expired tokens, role guard).
- Handlers tested via `httptest` + Gin test mode.
- Integration tests for auth service + todo service against a test DB (sqlite in-memory for CI friendliness, GORM-backed).

## Out of Scope

- Refresh tokens / logout token blacklist.
- Email verification, password reset.
- Refresh/rotation of JWT secrets.
- Advanced authorization (per-resource ACLs) beyond owner-or-admin.
- A docker-compose Postgres; Neon is used directly.
